# Retained standalone Source comparison

This additive Python operator interface separates a recorded original footprint
from current execution rights. It is a bounded diagnostic path, with no service,
CLI command, automatic recording, admission hook or activation. Existing
`resource_scopes.blocked`, processing, prospective, native, input and effect
checks retain their contracts.

`coordinator_runtime.retained_comparison` installs its additive schema when an
authorized operator opens `Store`. Opening a runtime, its journal or a Board
still needs genuine present access; this library does not supply that access.
The Maker's source/test authorization selects no actual journal operation.

1. While the original Source is still eligible under its own actual authority,
   genuine Work can explicitly call `record_current(runtime, {"id": job,
   "task": task})`. This uses the existing original standalone native mapper,
   including its original frozen task/admission, exact grant/proof, epoch/birth,
   packet/material, collector/context and current permission checks. It returns
   one immutable `{job, witness, scope}` pin. It never runs the Source. A missing,
   expired, revoked, excluded or unmapped original refuses. Duplicate recording
   cannot replace the immutable first witness.
2. Under independently genuine current journal data access, Work calls
   `select(runtime, boards, {"mode": "retained-comparison-metadata-v1",
   "purpose": "the actual limited purpose", "expires": finite_time,
   "pins": [original_pin]})`. The current acting session must be the configured
   genuine Work issuer. `ProcessingBoard.metadata_authority` verifies Work's
   original journal/grant binding under current configuration through
   `_original`, without calling expired processing authority. Current source,
   configuration, exact public footprint and witness pins are bound to the new
   grant. A request author, retained title or native-root assertion supplies none
   of these conditions. Selection of a missing pin cannot create its evidence.
3. `project(runtime, boards, key, job)` rechecks that current principal, source,
   configuration, finite metadata expiry/revocation and exact scope before
   acquiring the immutable witness. Source holds precede witness acquisition.
   It verifies the witness digest and original scalar job/source/birth/attempt/
   cap/epoch/call/context/collector relationships. It exposes no old packet,
   return, task body, private handle/run/session, receipt or arbitrary error.
4. `compare(runtime, boards, key, job, {"reads": [...], "writes": [...]})`
   compares that exact declared candidate against known original public read
   ceilings. It checks the entire candidate and original map lexically before
   filesystem metadata and refuses excluded operands. Alias or metadata failure
   yields `UNKNOWN`. A genuine write/read or write/write overlap yields
   `CONFLICT`. Named public footprints may be disjoint (`scoped_disjoint: true`)
   while the overall result remains `UNKNOWN` and `eligible: false`.
5. `revoke(runtime, boards, key)` appends a metadata-only revocation. It does not
   revoke or renew any original processing/native/input/effect right.

Every Source retains opaque native/account/executor/history/capture constraints
and physical `UNKNOWN`. The original unbounded flag is preserved. No private
native/executor namespace or its hash is exported as a footprint or statted by
later comparison. The explicit public task ceilings are a known subset, not a
complete executor footprint. This version therefore offers no positive operation
eligibility verdict, even if the named public paths are disjoint. Actual future
admission still needs its independently supported complete constraints, current
material, grants, finite allocation and acceptance. Integrating diagnostic output
into admission or adding native-owner/physical attestations requires a further
consequential decision; there is no hidden fallback to current task policy.

The immutable record preserves original launch proof (including task/admission,
capability and epoch), native-account policy/packet witness pins and public read
ceilings. It relies on the existing cooperative journal and SQL immutability, not
adversarial signatures or a native-owner attestation. It does not reacquire or
rehash original source/material/private bodies to reconstruct proof. Mutations of
unreleased original bodies cannot be independently detected by this metadata
path; no physical/control claim depends on them.

**Older originals without a recorded witness remain unsupported.** In particular,
this change does not authenticate the actual fa6 case, backfill a witness after
revocation, renew b976/630, or establish a lawful actual access basis. Missing
original witness/access/native-principal facts must return to genuine Work. This
is useful partial support under Decision1036, not a complete historical mapper
for all existing journal generations or a cutover result.
