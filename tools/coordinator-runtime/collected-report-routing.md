# Collected reports and an existing queued consumer

A collected report can preserve failed checks, dissent, inherited failures and
unknown downstream effects. Those are report content. They do not, by themselves,
make transfer to its assigned report reader an incomplete capture. Transfer is
separate from executing effects, owner callbacks, qualification and acceptance.

`software.collected_report` retains actual task collection, BEGIN/numeric END0,
complete capture/tool inventory, the original stored result, known actual job
effects, no source/job hold, and current member hashes. Its caller authenticates
the exact response and every original member, recipient, package, task/method and
launch grant. Existing software response anchors undergo the same checks as new
mappings. No `local_defect`, category or DONE marker supplies authority.

Only existing configured report edges are eligible: Work proposer → Work
integrator, Reviews proposer → sole Reviews integrator, Reviews integrator → Work
proposer, and QA execution → its package cleanup. Captured nonzero attempts are
preserved in those reports. Routines still undergo their completion assessment;
ordinary effects and QA qualification/acceptance retain their existing guards.
Native PARTIAL Source receipts keep their existing original-collector contract.
The clean-processing and owner-settlement checks remain separate and strict.
A published adverse result reuses its exact original response/consumer; enqueue
and pickup do not supply settlement or a processing timestamp.

## Whole-report transport without model retransmission

For an admitted finite Reviews `report_scope.integration_inputs` route, the prompt supplies each
frozen original envelope once, and `report_integration` declares the optional
`report-integration-v1` producer protocol. The model returns its new analysis,
decision, explanation of the current method, exact task/source pins, and coverage
of each supplied envelope in a typed finding. DONE requires complete current
envelope coverage and a substantive new analysis/decision; coverage is an
attributed model declaration, never proof of reading referenced artifacts or
performing a native review. Historical partial/unread evidence stays historical.

Software leaves the collected model result and its numerical collection intact.
It attaches `report_custody` to the response beside `body`: original collector and
attempt, model-result digest, and exact canonical collected-report envelopes.
The collector comes from the immutable original attempt, even after a successor
adopts closure. The job controller and `collection_handoff` describe separate
closure custody; transferring it neither rewrites nor invalidates this value.
JSON strings inside those envelopes retain their exact bytes. The next reader
receives the originals once plus separately attributed new assertions. Recursive
custody remains input on subsequent report integration. New-protocol results
must not echo a `collected_reports` finding; legacy exact whole-copy results still
validate. The combined custody and model result obey the existing result budget.

Original failures, unknowns, artifacts and handoffs remain inert attributed source
data. Software neither acquires their referenced files nor executes old intents.
Only the new model's declared artifacts and new handoffs enter the existing
acquisition/delivery checks. Informative failure returns also retain original
custody; PARTIAL/UNKNOWN/FAILED, numeric exit1, invalid analysis and incomplete
capture cannot qualify as a complete report. Ordinary clarification still
conserves the model's own prior return exactly. Transfer authenticates both the
unchanged model body and software custody against current frozen source rights.
Receiving Work must independently process and settle its own responsibility.

Finite QA cleanup retains the exact legacy QA template and its whole-copy
`collected_reports` finding. Its prompt declares no new transport protocol and
the validator requires the legacy serialization. QA model retransmission is a
bounded compatibility limitation; acceptance and original duties are unchanged.

Every new read group, including post-await finish, custody, transfer and
informative failure, checks all member hold/hash metadata and current source
authority before any member body. Refused informative delivery stays held with
its already collected original; it does not reacquire the withheld source.

Admission and batching still guarantee the accepted legacy return shape only.
Near the result ceiling the larger new Reviews composition can refuse: custody,
coverage and new analysis must all fit the same selected limit. No budget is
raised, source truncated or legacy return invalidated. This remains a scoped
no-copy feasibility followup, not whole-runtime completion.

This protocol does not repair or replay a previously failed original. Its owner
must separately select a lawful fresh-input or remaining-work transition.

## Same-location code repair

A normal prospective configuration transition advances the source frontier. It
cannot continue an already-owned queued response below that frontier. The
`collected-report-repair-basis` and `select-collected-report-repair` commands
instead select one immutable receipt in the SAME journal, retaining the SAME
configuration, processing capability, prospective authority, finite allocation,
frontiers, original receipts and capacity charges. No normal grant is revived.

This interface permits only the report/interface modules named by
`report_repair.MODULES`, at the SAME release location. All other release files,
templates, SDK/provider dependencies and pool controls must remain identical.
It is not a general deployment or historical recovery API. Work must have actual
reviewed code evidence. The receipt binds exact current bytes, original grant
bindings, the unstarted queued responsibility, its report/producer and the
original stopped collector. Source/rights changes refuse rather than replay.

The actual owner must first stop the original service, collect that SAME
foreground process's real numeric END, and use `processing-release` with actual
parent evidence. A returned service record or free cooperative lock alone is
insufficient. Work then deploys the reviewed compatible code at the same release
location using its own adoption authority, takes the bounded repair basis and
selects `{basis, authority, evidence}`. After selection, the ordinary existing
`processing-service CAPABILITY --enable-models` command uses a NEW collector for
the existing queued consumer. It does not resume or impersonate the old original.

Repeated identical selection returns the original receipt, even after consumer
reservation. Changed requests, changed pins, revoked/expired rights, missing
collection, source holds and ordinary backpressure refuse. The repair does not
renew finite expiry/windows. If those rights are no longer current, return the
specific dependency to actual Work; do not rotate a future-only boundary as a
substitute. Existing review/effect/source/consumer/outbox/privacy/retention debts
and unselected duties stay with their original custodians.

## Reservation diagnostics

`processing-source CAPABILITY EVENT --diagnostics` includes only that selected
current source's last recorded reservation refusal. New records bind controller,
capability, source hash, queue and task. It reports whether the same controller is
serving and the consumer is still queued; neither means a fresh attempt or
liveness. Old source/role-only records explicitly lack controller/hash/capability
attribution and retain unknown currentness. Only a small public refusal vocabulary
is exposed; arbitrary exception bodies and global errors are withheld. Empty
controller `phase_errors` is not processing progress or acceptance.

The focused fixtures use a disposable journal/SDK and authored collector/tool
facts in a network-isolated mount namespace. They are producer verification,
not independent QA, native acceptance, live repair or full rollout qualification.
# Forward reference transport768: gated source prototype

`software-report-reference-v1` is a distinct software custody version. It does
not change `report-integration-v1` model analysis or reinterpret old inline
v4/v5 results. The forward selector is an optional `transport` object inside
the existing finite `reviews_report` policy, with `version`, `max_model_bytes`,
`max_origins`, and `max_read_bytes`. **Selection currently refuses:**
`report_reference.RELEASED` is false. This source is not a deployable reference
consumer release. No current held producer repair or recovery is authorized.

The prototype freezes each whole canonical current event into existing
`artifact_blobs` and a distinct `artifact_custody` origin record. Responses carry
ordered immediate origin descriptors, the original attempt/controller, and the
unchanged model-result digest. Prior reference links stay inside immutable
original events; they are not recursively expanded into new response custody.
Old inline custody is frozen opaquely without reopening historical artifact
paths. Source identity is the event plus its recorded custodian, not a blob
hash. Snapshot paths are software-owned logical origin names, never arbitrary
path lookup capabilities or instructions to inspect the runtime journal.

The actual prompt entry resolves same-journal links under a cooperative source
transaction, admitting every current member and required origin before body
acquisition. It checks current holds, source hashes, selected capability, finite
policy, epoch/grants, recipient/task binding and the existing blob origin,
exclusion, stage, prefix and bounded-log guards. Calls after await repeat this
admission. Naked blob access is refused. Required approved bytes are copied
through guarded frozen materialization; existing materializations are read back
and authenticated. All unique closure bytes and snapshot/materialization costs
remain bounded by selected read, artifact and cumulative storage limits.

Each consumer must separately declare a `report-reference-read-v1` finding with
ordered immediate `{event,sha256}` sources, `closure` whole/partial/unread and
text `limits`. DONE requires whole current inputs and required closure. This is
an attributed read declaration, not proof of model thought: descriptor fit,
existence, software hashing and synthetic fixtures do not establish actual
provider reading. Reviews still owes its separate current typed analysis.
Full-history reading still has real input/context cost.

Selected response, handoff, owner-question and informative-failure paths check
their software transport representation in UTF-8 bytes. Actual wrapper checks
can refuse despite descriptor admission; originals remain collected. The
prototype's model allowance is explicit, not assurance that arbitrary new
analysis fits every wrapper. Unselected inline and QA paths keep their existing
serialization and decisions.

Origin records conservatively pin the entire original event/result/custodian
cohort through the existing retirement eligibility gate. This intentionally
provides no pin-release/GC feature; it may retain settled origins longer than
24 hours. END, DONE and ACK never start the processing-plus-24-hour clock.

Remaining release blockers include exact addressed consumer/owner report-origin
export (direct `artifact-source` explicitly refuses), complete delivery wrapper
accounting at the external boundary, imported-origin authority and exhaustive
cycle/contradiction/corruption qualification, and independent review of the
complete consumer/recovery/retention composition. Unsupported imports refuse;
the original held v5 code-pin/owner redispose bridge is a separate interface and
is not implemented. Existing repair allowlists and original results are intact.
