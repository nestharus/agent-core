# Stopped owner source amendment

`stopped-owner-source-amendment-v1` appends source selections underneath an existing `continuing-owner-lease-v1`. It never updates that immutable plan, the original processing selection, grants, epoch, source birth, queued inputs, jobs, attempts, control results or charges. It does not import historical capabilities or replay consumers. The effective source is the latest appended selection, while the original finite owner plan remains the authority ceiling. At most 24 selections fit within the same original plan; expiration and absolute input/start/window/byte ceilings remain effective.

This interface supports subsequent independently reviewed repairs within a fixed module ceiling: the existing lease modules plus local_integration, inputs, contracts, software and completion. Each actual delta must be enumerated exactly. Adding/removing modules, dependencies, templates, config, SDK, pool location/control, task authority or unrelated production files refuses. Tests and coordinator Markdown documentation may accompany the exact production delta. The source branch must descend from the exact preceding selected commit, with exact commit, tree and **all** parents recorded. Every previous/current implementation hash is authenticated against its Git blob as well as the installed public release. An initial amendment binds the supplied prior publication to the original plan's selected implementation; later amendments require the exact prior appended commit.

The installer and actual parent own stop/END/release and installing reviewed code at the existing public root. A running original must first return, its actual parent must collect the SAME numeric END and use the existing `processing-release`. Every recorded service/processing original must be stopped/released; uncollected attempts or reserved/running jobs refuse. Pending consumers and held duties remain. Installing the candidate makes ordinary processing refuse until this explicit operation selects the new source; the candidate basis deliberately checks the prior immutable selection and installed candidate directly, without requiring normal current-source Access first.

Use the existing installed `coordinator --config SAME_CONFIG` entry point. No operation below starts a model, native tool or effect. All JSON paths are explicit public records selected by their actual owners.

1. Genuine Work prepares `PREVIOUS.json`: `{ "commit": "EXACT40", "tree": "EXACT40", "parents": ["EVERY_PARENT_IN_GIT_ORDER"] }`. Obtain it from the independently reviewed prior PUBLICATION, and authenticate it through Git. For the initial live lineage this is original822, not historical23773. Do not guess a future composite hash.
2. Finalize the five safe reports for the actual installed candidate and prepare `MANIFEST.json`, an object mapping **only** `PRIMARY.md`, `RESULT.json`, `LIMITS.md`, `PUBLICATION.json`, `WRITER-RELEASE.json` to their exact SHA256 values. These immutable report pins are part of the basis; later report changes require fresh review. A hash string alone is not review acceptance.
3. Genuine Work runs `owner-source-amendment-basis CAP --controller RELEASED_ORIGINAL --previous PREVIOUS.json --manifest MANIFEST.json --module cli.py --module report_repair.py --purpose ACTUAL_PURPOSE`. Repeat `--module` for the complete actual delta in sorted order, including subsequent repairs' modules. Save the returned object as `BASIS`.
4. A distinct actual configured Reviews owner independently reviews the final exact source and report manifest, collects its review's successful numeric END, and supplies `{ "basis": BASIS, "authority": "ACTUAL independent review and collection evidence", "actual_END": 0 }` to `review-owner-source-amendment --selection REVIEW.json`. The current Reviews session must authenticate via the normal actor check. This appends an immutable review, returning `review_hash` and `basis_hash`. Work testimony or arbitrary evidence strings do not substitute for this separate actor's receipt. The END field is that authenticated reviewer's attestation; this interface does not independently observe an OS process.
5. Genuine Work prepares `{ "schema": "stopped-owner-source-amendment-v1", "basis": BASIS, "authority": "ACTUAL Work decision", "review_hash": "RETURNED_REVIEW_HASH" }` and runs `select-owner-source-amendment --selection SELECTION.json`. Changed source/authority/counters or a stale basis refuses and needs a new basis/review. Selection appends one record inside the cooperative stopped lock and journal transaction, then validates normal Access. It does not replace the owner plan. Exact retry returns the same receipt while the source and finite authority remain current. Contradictory retry refuses.
6. Preserve the returned receipt, including previous/current commit/tree/all parents, amendment/plan/review hashes and module/manifest pins. The original `owner-lease-status CAP` remains the authority status; the explicit source receipt is separate. Parent alone decides whether to restart an ordinary foreground processing service after its independent prerequisites. Future source repairs repeat this protocol using the last source receipt as PREVIOUS.

The journal transaction is atomic for cooperative writers. The protocol does not promise hostile-writer CAS, filesystem snapshot atomicity, global all-clear, source installation, native acceptance or renewed effects. Original raw native/effect epoch expiry remains effective even while the finite framework lease continues. Independent report hashes are immutable attributed reviewer claims, not an external signature-verification service. Actor identity, prior publication, stop and actual review collection are obligations of their genuine custodians.
