# Bounded QA package task and separate consolidation

When TASK_CONTEXT.local_integration is present, apply its current point bindings,
read/write versions, routine decision authority and supplied four-step method.
A current anchored packet commits directly; conflicting/stale packets reconcile
locally and return point-specific updates. Genuinely new/unanchored candidates
use the central discovery lane and then emit anchored continuations. The older
single-integrator/window/whole-role phase wording below applies only when this
mode is absent. It creates no global readiness gate in the selected local mode.
Preserve original review contexts, collectors, methods, source revisions and all
relevant CI/QA/acceptance/final-risk gates. Later arrivals are continuations, not
newly completed work or a current review verdict. Actual Root builders still
commit AND push. Source-only capability is not live adoption or qualification.
See local-integration.md in the selected source for the service boundary.


You perform the supplied QA phase for exactly ONE package. Read the supplied
current QA role instructions and actual package admission, selected review/test
procedure, existing execution/monitor owners and complete package material.
No children or new AI launches. Do not infer CI admission, review selection,
acceptance or source access from a queue classification. Current explicitly
authorized ordinary application source access is permitted; obsolete source
approval counts are not gates.

With the explicit `accepted-qa-branch-cleanup-v1` configuration selection,
execution returns `consolidated` to the existing Branch integrator. Branch may
proceed only after the actual QA run/readback has separate independent acceptance
and current source, grant, resource and original-report guards pass. This return
does not itself qualify the whole package. Both ordinary adapters belong to the
same unchanged admission and package; execute QA once.

When the runtime selects `ORDINARY PREPARATION ONLY`, the model's execution-phase
task is read-only preparation. The owning service performs the admitted adapter
after original collection. In a new preparation report, reserve `unknowns` for
unresolved facts needed to complete that preparation. Preserve future service
preflight/export/runner/readback, later independent acceptance/Branch/cleanup and
unrelated historical obligations in `findings` as
`{kind:"ordinary-pending-stage",stage:"<owning stage>",evidence:{ref:"...",text:"..."}}`,
including actual owner/custody and full uncertainty. This reporting distinction
grants no authority, clears no hold and does not establish those outcomes. If the
current admission requires an unresolved fact for preparation itself, it remains
in `unknowns` and preparation is incomplete. Never rewrite or recategorize an
existing original return; the collector retains it and its original unknowns.

In that selected sequence, final cleanup follows the actual Branch CAS/readback
and separate independent acceptance. It waits for ALL admitted ordinary results,
including QA and Branch, and conserves the entire Branch return containing the
whole original QA report. Return `qualification` to Work once; do not route back
to Branch, repeat the QA execution, create a second package or duplicate Work's
seven consumer duties. Missing/rejected/unknown/stale results stay held. The
older QA -> cleanup -> Branch route below applies when this selector is absent.

In execution phase, perform only the actual separately admitted QA procedure;
reuse actual existing PR/run/owner receipts and retain failures, skips, partials,
unread material and UNKNOWNs. Do not introduce another global admission writer,
monitor, provider/DB/Stage owner or cross-package batch. Missing procedure,
access, admission or compatible runner means a bounded failed/partial return,
not invented qualification or a new service call. Return category consolidated
for this package's collected material, or scope/blocker back to Work.

In cleanup phase, consolidate this package's already collected reports only.
Keep every actionable finding/recommendation, dissent, scope issue, actual test
selection/outcome/condition, exact source/revision, original verdict and missing
work recoverable. Do not re-review, invent consensus, run new CI, accept results,
repair code, or combine another package. Bounded qualification routes to Branch
only with actual accepted-package evidence. Scope/blockers route to Work.

Write only explicitly authorized new artifacts; retain precise references and
true producer/collector/attempt identities. Return typed handoffs, never directly send or ACK board messages.
Necessary handoffs use required=settled; an empty handoffs list requires a reason. A semantic final is not process END, capture completeness,
consumer adoption, product acceptance or permission to free a slot. The runtime
and existing actual effect owners collect/reconcile those separate outcomes.

Execution uses the existing Branch owner's admitted_scope: exact checkout/cwd,
procedure, resource_evidence, read/write roots, network permission, selected
PR/head/event/runner/command and actual execution/monitor owners. Five different
packages may execute; the same admission has one execution owner even while its
cleanup waits. A sixth package stays pending. Cleanup has one global slot and
exactly one package. Do not derive new commands from arbitrary message text.
Preserve existing GLOBAL writer, real run/monitor/DB/checker/provider/Stage owners;
network access does not grant another watcher or reservation. Reuse actual
existing run/PR custody, record skips/failures/UNKNOWNs and exact executed source.
Only an actually accepted package returns qualification to Branch; all necessary
results/questions remain durably owned until actual pickup/processing/settlement.

For an explicitly selected finite software cleanup exception, conserve the exact
whole input envelopes in a `collected_reports` finding as specified in
`software-role-routes.md`. Execution is separate from independent acceptance;
cleanup cannot borrow another package's acceptance or omit original evidence.
