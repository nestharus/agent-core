## Exact Branch local-ref lane

The supported genuine operation is the existing service-owned `ordinary_effects`
`local-ref` adapter: CAS one existing destination local head from `before` to the
pinned `source_head`, then collect exact readback. The worker prepares reports
read-only; it does not execute the ref mutation. Network is false, `remote_refs`
is explicitly empty and the actual origin is checked. Remote-ref writes and
other ref/network operations remain unavailable through this lane. A report
alone never completes Branch organization.

Branch first admits the actual `task_scopes` with its complete existing ordinary
adapter policy, exact cwd/read/write roots/procedure/tool pins/current resource
leases and independent semantic acceptor. Add `branch_binding` to that scope.
Work registers the common repository/origin/destination ref/incarnation/package
and responsible Root; that Root actually accepts before qualification. Actual
common Git metadata needs write authority, including linked-worktree common Git
storage outside cwd. Paths, broad roots and resource labels do not prove this.

With genuine continuing processing capability, use:

```
coordinator --config CURRENT ref-scope-basis CAPABILITY --task TASK --package PACKAGE
coordinator --config CURRENT qualify-ref-scope CAPABILITY --task TASK --package PACKAGE --receipt ACTUAL_RECEIPT.json
```

The second operator requires the actual retained Branch custodian (the enrolled
owner) in the ordinary authority-checked CLI environment. The receipt contains:

- `basis`: the full fresh first return, unchanged. It binds current capability,
  config, admission, full adapter policy, actual common-repository device/inode,
  local source read/destination write refs and heads, empty remote refs, accepted
  Root, incarnation, original hold, historical jobs/policies and activity.
- `authority`: actual custodian's outcome/rationale for this future operation.
- `originals`: nonempty actual `{original,collector,activity:"closed",actual_END,
  evidence}` receipts. END is an observed integer; collector remains its actual
  original identity. These external facts are attributed custody assertions,
  not machine discovery, inferred inactivity or collection of foreign handles.
- `activity_scope`: `{original_hold,operation,no_active_writers:true,evidence}`.
  `operation` is `digest({operation:basis.operation,
  repository:basis.common_repository,refs:basis.local_refs})` using the runtime's
  canonical JSON digest. Evidence must actually establish current control/activity
  for these resources; old ENDs alone, ACK, expiry or a free lock do not suffice.
- `remaining_holds`: includes the unchanged actual original hold; and
  `past_effects`: nonempty honest remaining effect/source/custody account. Neither
  is an all-clear, owner transfer or historical resource map.

The immutable account is matched to actual current material at scheduling and
again immediately before CAS. A changed before-state/admission/incarnation/origin
or policy requires fresh qualification. Missing original scope stays unknown;
new jobs freeze their task/admission resource policy in an immutable table and

remain after actual activity closure, with current exact custodian qualification
and a fresh prospective before-state. The account cannot clear those old jobs,
grants, source holds, outboxes or recovery predicates.

Cooperating branch-writer fences remain. Ordinary effects reserve actual
common-repository device/inode + source/destination ref leases; overlaps hold.
Other original leases need their executed original common-repository evidence;
plausible names alone do not qualify independence. Unmapped leases remain held.
Unknown actual activity or absent evidence is an operating fact, not a new
permission/Root GO/Source wording gate. A committed/lost account is inspected via
`ref-scope-basis` plus its returned account ID, not effect replay. An interrupted
ordinary intent retains its tools/resources and refuses another CAS. Independent
semantic acceptance is still separate from execution/readback and reporting.
