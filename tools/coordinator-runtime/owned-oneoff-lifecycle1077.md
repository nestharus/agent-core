# Owned one-off recovery and custodial boundary

This candidate extends the existing dispatcher, journal, collector and retention
gate. It is not installed, accepted or authority to operate an account.

`Dispatcher.run_model` persists the exact prompt, execution specification,
response schema, frozen job membership, binding and original collector before
calling the model adapter. The existing Work/Branch/Reviews/QA task routes,
classifier, diagnosis and metadata-mapping callers use that method. Other
workstreams do not acquire coverage by labeling an ID or creating a row.

The adapter checkpoints its bounded return and available tool/capture evidence
before unsubscribe/teardown. A per-launch terminal reservation participates in
the existing cumulative storage admission. A failed checkpoint cannot bypass
owned teardown or original numeric exit collection: its error/recovery duty
stays held. Finite capacity is backpressure, not permission to discard input,
raise production limits or claim complete recovery. Exact effect reconstruction
and required external recovery material can still be missing.

Original `Store.collect` seals the snapshot to that same original's durable
result, session, capture and collection fields. Model return bodies cannot issue
this seal. Changes or missing evidence keep retirement held. Launch and terminal
records are immutable; required context remains in the existing journal under
its byte limit. This change does not purge journal history or provide indefinite
bounded growth when custody cannot be released.

Within already lawful current journal/source access, the existing owner may call
`oneoff.snapshot(store, attempt)` to recover retained context after session exit
or controller restart, without resuming or adopting the old process. Existing
execution/privacy/source admission precedes body access. For completed
classifiers the current-classification admission can refuse this view; the
retained context is not lost, but a later lawful recovery-access interface is a
remaining dependency. No expired execution grant becomes current access.

`oneoff.retirement_state` uses the same original event membership and existing
whole-processing, descendant, consumer/outbox/effect and processing+86400-second
checks. It never turns a qualified processing window into deletion authority.
The ordinary sweep also rechecks snapshot/terminal/collection integrity. Human,
current-use, privacy, recovery and all other existing holds remain authoritative.
Unknown and unregistered historical records receive no retrospective ownership,
inventory, freeze or retirement credit.

`oneoff.residual_handoff(store, attempt)` reports only a producer-observed root
bound to the original attempt. It retains the original collector and routes the
missing answer to the existing runtime actor. It does not appoint a custodian.
The actual lawful custodian must supply current authority, version/endpoint,
exact cascade/auxiliary scope, independent headless/current-use facts and every
hold, then actual intent/postcondition receipts under a later selected action.
Unknown residual identities stay with genuine Work for an exact safe handback;
there is no account inventory or arbitrary-ID registration path here.
