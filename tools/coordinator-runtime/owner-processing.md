# Explicit software owner processing

The `processing-*` surface lets the genuine original Work issuer delegate
routine consumption in the **unchanged original software journal** after its
ordinary grants and intake have stopped. It uses the existing dispatcher,
Codex CLI subprocess collectors, fresh Luna LOW classification/ACK, Work-xhigh
workers, frozen reservations, role integrators and QA execution/consolidation.
It neither reenrolls native owners nor unrevokes any ordinary/retained grant.
This source interface has protocol tests, not live operating qualification.

Only actual Work uses these commands in its existing genuine issuer context.
Never set identity, HOME, profile or credentials to invoke them. The original
configuration must already select Work software delegation and an enabled,
schema-qualified runtime. Unsupported source/library/membership/authority is
an exact dependency; no grant acquisition or second orchestration service is
performed automatically. Every command opens the runtime/schema; names such
as `basis`, `source` and `status` are not a read-only filesystem guarantee.

## Parent operation

Use the candidate `coordinator --config ORIGINAL_CONFIG` prefix throughout.

1. `processing-basis` returns exact original grant/config/source hashes,
   residency, each role's future post frontier and original scan cursor, plus
   current capability IDs for lost-response recovery. Preserve the full result.
2. Prepare one selection JSON with **exact** keys:

   ```json
   {
     "basis": "REPLACE WITH THE WHOLE ACTUAL BASIS OBJECT",
     "authority": "actual selected Work authority and bounded purpose",
     "expires": 0,
     "retained_events": [],
     "recover_controls": {},
     "future_intake": false,
     "tasks": [],
     "max_starts": 32,
     "max_shared_rows": 100000,
     "max_shared_payload_bytes": 536870912,
     "max_runtime_rows": 512
   }
   ```

   Select actual retained event IDs and existing task names; no guessed tasks,
   native identities or renamed source. Set an actual expiry no more than one
   hour ahead. The sample ceilings express a finite policy, not current fit,
   reservation, physical quota or permission to expand original entitlement.
   `recover_controls` is an explicit event-to-original-attempt map for consuming
   an already collected return under a new capability; it grants no replay.
3. `delegate-processing --selection SELECTION_FILE` issues one capability.
   Preserve its exact ID/issuer. A refused or interrupted issuance is not
   automatically retried. Recover exact metadata with `processing-basis`.
4. `processing-source CAPABILITY EVENT` exposes selected full source,
   resolution and responsibility. `processing-run CAPABILITY --seconds 600
   --enable-models` runs one bounded controller. Launch it as the parent's
   actual background terminal command; retain argv/PID/capture and collect
   **that same original** to its real numeric END. The controller emits its
   own durable controller ID before model scheduling. Expiry/stop drains its
   own children; it does not take over a foreign collector or infer their END.
5. Read `processing-status CAPABILITY` and ordinary `status` fully. Preserve
   errors, partial captures, exact attempts, duties and effects. No exit0,
   triage, ACK, successful sweep, slot release or JSON final proves processing.
6. After actual parent collection, `processing-release CAPABILITY --controller
   CONTROLLER --receipt RECEIPT_FILE` records `{ "actual_END": INTEGER,
   "evidence": ["actual original collection and full-return evidence"] }`.
   Uncollected attempts refuse release. A crashed/uncollected controller is an
   exact original-collector dependency, not permission to start another.
7. `revoke-processing CAPABILITY` closes only that capability. No original
   grant, queue, hold, source, outbox, recovery record or pool turn is reset.

If collection succeeded but local disposition was interrupted, use
`processing-apply-control CAPABILITY EVENT --attempt ORIGINAL_ATTEMPT`.
This consumes the exact retained worker return, never starts a replacement.
Expired/revoked authority needs an explicitly selected recovery capability
with that exact event/attempt. A failed/partial/unknown return remains a
specific dependency with its original collector and result; there is no
automatic control retry or business replay.

## Meaning and remaining authority

Native owner, genuine Work issuer, explicit software actor, actual model
worker/controller, implementation Root and final human/Adam remain distinct.
Control processing requires a meaningful Work-xhigh return, matching immutable
source, complete tool capture, observed actual worker identity and collected
original numeric END. Its attributed resolution records the **software actor**
and exact worker proof. A fresh Luna classifies the derived resolution before
the existing queue can advance. No native full-read or human consent is claimed.

Posted alert/question/effect-request deliveries get one durable exact receiving
intent in the existing software delivery table. Managed transport and original
source/receiver grants are checked. Software settlement requires actual control
handling, fresh classification/ACK, a done control queue and no remaining
obligations. Uncertain native sends/control duties remain with their effect
custodian. Work/result handoffs continue through existing task handoff policies
and actual collected job proofs. Missing handoff routes, absent source work,
external holders or uncollected originals are dependencies, never fake reviews.

The selected Reviews opaque `execution=owner` procedure is preserved. This
adapter does not implement its external executor: the exact selected procedure
holder must supply its supported execution/return. The dependency is visible
while independent admitted work continues. QA scope/admission, real integration,
ordinary effects and independent acceptance stay with existing contracts.
The adapter enforces five separate QA execution packages followed by one
consolidation slot; execution batches are never combined. Integrators remain
one per role, with a frozen batch. Source-defined response routes preserve
Root corrections, Work scope/blockers and actual Branch/Reviews/QA holders.

An existing role effect hold still blocks its held phases. Read-only proposers
may operate independently of that hold; they cannot release it. No canonical,
ref, QA, CI, Stage or acceptance authority is supplied by this capability.
Actual original effects need their supported scoped owning-role disposition.

`future_intake=true` admits genuinely new posts after the recorded per-role
frontier. The earlier original-cursor-to-frontier interval is **conserved
unscanned debt**, not read/ACKed/processed. Earlier selected source IDs retain
their old event/grant hashes and attempts; future intake cannot reclassify or
replay them to shed obligations. No new journal resets cumulative capacity.
Recurring unchanged violations and no-violation silence use the existing alert
engine. The current public pool determines every reservation and admission;
the adapter neither edits it nor supplies a profile flag or fallback.

Runtime storage and starts remain bounded by original accounting and the new
finite start allowance. Board shared rows/serialized payload and cumulative
same-runtime logical rows are distinct from disk allocation or all platform
bytes. Checks are cooperative, not multi-file atomicity or noncooperating CAS.
No cleanup/custodian authority is included. Retirement still needs actual
processing+24h **and every** source/consumer/outbox/recovery/effect/privacy hold.
