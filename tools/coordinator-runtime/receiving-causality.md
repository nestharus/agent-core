# Bound Source acquisition and receiving completion

A service-bound Reviews attempt rechecks its current processing and software
authority immediately after binding, before preparing input or acquiring review
material. A package-scoped Source also checks the selected component paths
against its current admitted read/write roots before repository acquisition.
Component/origin/pin selection remains independently necessary; it does not
replace the delegated task scope. An exact source-file read grant is sufficient
for that selected file; no repository-parent grant is required. Independent
Source execution without a package-scoped task retains its selected component
authority and does not acquire a new package requirement.

`execution=owner` describes the task procedure. The external owner-return
contract belongs to its original same-role `work` delegation. A Source's
same-role `result` instead keeps its actual software collector receipt, original
attempt/result hash and false native/full-owner-read flags. An external owner
return still requires its actual originals, method, coverage, custody and
effects evidence. Neither receipt can substitute for the other.

A published response can be both the original result outbox's event and its
linked receiving source. Its global processing timestamp must await that
outbox, so the incoming receipt cannot itself await the same global timestamp.
The delivery frontier identifies the exact published-response outbox, original
producer/attempt, payload and persisted receiving link. It evaluates the same
event-completion predicates with only that incoming edge excluded. Every
receiving job, remaining obligation, effect/publication, child response and
outgoing delivery remains required. This produces evidence for the incoming
receipt; it does not mark an event processed. Normal event processing and the
whole-processing retention clock still join the settled incoming edge. Pending
reservations produce pickup only; absent workers do not imply a processing
failure or a completed consumer.

For future software receiving, the operator must select exact producer
`software_handoffs` recipient/task maps and include each receiver in the current
prospective task/grant population before source birth. Reviews consolidation to
Work and QA qualification to Branch are distinct routes. The receiver needs its
own current software authority and any actual package scope. QA execution still
requires its admitted operation, independent acceptance, narrowed cleanup,
current qualification and separately admitted Branch receiving. A published
response or available task name supplies none of these rights. Missing policy
remains an operator return; it does not authorize native pickup, a broad grant,
historical re-admission or automatic settlement.
